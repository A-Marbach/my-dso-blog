# Conduit Docker Project

Docker Compose setup for running the Conduit application with a Django backend and Angular frontend.

The project demonstrates containerized application deployment, persistent configuration, image delivery through GHCR and automated deployment with GitHub Actions.

## Architecture

```text
GitHub Repository
       |
       v
GitHub Actions
       |
       v
GitHub Container Registry
       |
       v
Linux VM
       |
       v
Docker Compose
   |        |
   v        v
Backend   Frontend
```

Backend and frontend images are built in GitHub Actions and stored in GitHub Container Registry.

The Linux VM pulls the pre-built images and runs the application with Docker Compose.

## Quickstart

### Prerequisites

- Docker
- Docker Compose
- Git

Clone the repository:

```bash
git clone git@github.com:A-Marbach/conduit-container.git
cd conduit-container
```

Initialize the frontend and backend submodules:

```bash
git submodule update --init --recursive
```

Create the backend environment file:

```bash
cp backend/.env.example backend/.env
```

Start the application:

```bash
docker compose up -d
```

Check the running containers:

```bash
docker compose ps
```

The application is available at:

```text
Frontend: http://<server-ip>:8282
Backend:  http://<server-ip>:5000
```

## Environment Variables

Application configuration is stored in environment variables.

| Variable | Description | Example |
|---|---|---|
| `DJANGO_SECRET_KEY` | Django secret key | `changeme` |
| `DATABASE_NAME` | Database name | `conduit` |
| `DATABASE_USER` | Database user | `user` |
| `DATABASE_PASSWORD` | Database password | `password` |
| `DATABASE_HOST` | Database host | `db` |
| `DATABASE_PORT` | Database port | `5432` |

Sensitive values should not be committed to the repository.

Check container status:

```bash
docker compose ps
```

View logs:

```bash

```

Restart the application:

```bash
docker compose restart
```

Stop and remove the containers:

```bash
docker compose down
```

## GitHub Actions Deployment

The deployment workflow:

1. Builds backend and frontend Docker images
2. Pushes the images to GitHub Container Registry
3. Connects to the Linux VM through SSH
4. Pulls the latest images
5. Restarts the containers with Docker Compose

```text
Push to GitHub
      |
      v
GitHub Actions
      |
      v
Build Images
      |
      v
Push to GHCR
      |
      v
Linux VM pulls images
      |
      v
Docker Compose starts containers
```

The VM does not build application images itself.

Workflow:

```text
.github/workflows/deployment.yaml
```

## Security

- Environment files are excluded from version control
- Credentials and SSH keys are stored as GitHub repository secrets
- Application secrets are not hard-coded into frontend code
- Docker images are built in CI instead of directly on the production VM

## Troubleshooting

Check container state:

```bash
docker compose ps
```

Inspect application logs:

```bash
docker compose logs
```

Check individual service logs:

```bash
docker compose logs backend
docker compose logs frontend
```

Verify listening ports on the Linux server:

```bash
sudo ss -tulnp
```

If the application is not reachable, also verify firewall rules:

```bash
sudo ufw status
```
